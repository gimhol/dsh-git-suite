# Usage and features

[English](USAGE.md) | [中文](USAGE.zh.md)

`dsh-git-suite` adds a Git panel to DSH Web: history, branches, diffs, commits, pull requests, and the usual remote actions.

## Usage

- **Where to find it**: the left sidebar's **Git** entry, the right panel's **Git** card on its Start page, or **Ctrl/Cmd+Shift+G** from anywhere (rebindable in DSH's keyboard settings). Both places render the same panel.
- **Pick a repository**: use the project dropdown (type to search) or the **+** menu beside it to **clone a remote** or **select a local** repository. The right panel opens on the repository of the current session by default.
- **Views**: the **History / Commit / PR** switch in the second row. History shows the commit graph and details; Commit shows the working tree; PR appears when the remote is hosted on GitHub, Gitee, or GitLab and lists that forge's pull (or merge) requests.
- **Commit**: stage whole files with the row buttons, single hunks with **Stage this hunk**, or a dragged line selection via the right-click menu, then write a message (↑ walks this repository's recent messages) and press **Commit**. **Amend last commit** and **push after committing** are optional.
- **Diffs**: every diff has a layout toggle between unified rows and side-by-side columns, and code is syntax-highlighted by the file's language (50+ common languages; unknown types stay plain); Markdown fenced code blocks are highlighted by their fence language too. `.m` currently maps to Objective-C; use a `matlab` fence label for MATLAB snippets.
- **Everything else**: right-click branches, tags, stashes, remotes, commits, and files for their menus (checkout, merge, rebase, cherry-pick, reset, stash, tag, …); the top-right buttons open a terminal and the file manager, and open the repository in the detected editor (VS Code, Insiders, Cursor, Windsurf, VSCodium, Zed, Sublime Text, TextMate, a JetBrains IDE, Visual Studio, or Android Studio).

## Features

- **History**: paged loading, commit graph, commit details, and per-file patches in a unified or side-by-side diff viewer; sticky header, resizable columns, and virtualized rows.
- **Refs tree**: branches, tags, remotes, stashes, and submodules with search; double-click a local branch to switch; open submodules and return to the parent.
- **Working tree and commits**: stage/unstage whole files, single hunks, or a dragged line selection, review diffs, commit or amend, push after committing, and generate commit messages with AI.
- **Git LFS**: LFS-tracked images and audio are read through the smudge filter, so a real preview appears when the object is local and a clear "not downloaded" note replaces a broken image when it is not; commit details and working-tree diffs describe an LFS file as its pointer's object id and size instead of `version`/`oid`/`size` text; file lists show an **LFS** tag rather than pointer line counts; such files stage only as a whole, because a partial stage of a pointer would corrupt it; AI commit messages, staged reviews, and pull-request drafts get an object note in place of pointer rows; and an LFS failure (missing git-lfs, an undownloaded object, a remote refusing LFS uploads) returns a clear `lfs-failed` message instead of raw filter output.
- **Remote actions**: the history/commit switch, pull/push/fetch with remote, branch, prune, tag, and force options, merge/rebase, rebase onto any ref, and a commit context menu for tag/branch/checkout/cherry-pick/revert/reset.
- **Pull requests**: browse open, closed, or all pull/merge requests for GitHub, Gitee, and GitLab remotes, with a search box over the loaded rows and scroll-to-load paging; read the description and discussion (both rendered as Markdown), review and CI status, commits, and changed files with syntax-highlighted diffs; description, AI review, files, commits, and discussion can each be collapsed, with discussion pinned to the bottom; open a request in the browser; check one out locally as a `pr/<number>` branch (a clean `git status` is required; uncommitted changes are rejected with a clear message); merge it (merge/squash/rebase where supported, optionally deleting the source branch); close it, or reopen a closed request; or create a new request from the current branch with a title, description, base branch, and draft flag. Clicking the detail's **AI review** first opens a dialog to choose the context mode: temporary worktree (reads complete files, then removes it), full files through the forge API, or diff only; the last choice is remembered. The AI review is rendered as Markdown (headings, lists, code blocks, tables, links). While it runs, the panel streams the model's thinking, an output preview, the attempt number, and character counts, with a stop button; diff and full-file budgets adapt to the model's context window. The review stays local and is never posted to the forge. The Gitee merge dialog shows **Approve review** and **Mark test passed** buttons backed by Gitee's APIs; the detail and dialog show the review/test state (not assigned, pending, partially passed, passed). They only record the state and do not run tests. GitLab merge requests additionally offer **Delete PR**, guarded by a danger confirmation; it is permanent and keeps the source branch. GitHub and Gitee have no delete API, so those requests can only be closed. Private repositories use a token from `GITHUB_TOKEN`/`GITEE_TOKEN`/`GITLAB_TOKEN`, `gh`, or the credential helper; the token is stored through the helper and never reaches the page.
- **Cross-repository requests**: add the upstream repository as a remote (for example `git remote add upstream …`) and select it in the PR toolbar; the toolbar pill shows the list repository, and the detail shows the `head → base` repository. The checked-out branch must track its fork remote (for example `origin/feature`); the create form then opens a fork → upstream request. Both remotes must be on the same forge and host. Viewing, checking out, closing, and merging existing upstream requests work the same way once the upstream remote is selected.
- **Credentials**: a push or pull that fails on authentication offers a username/token dialog; the credential goes into the OS credential store through the repository's git credential helper and the action retries once (SSH remotes point at ssh-add instead).
- **Right panel**: the same panel in DSH's right sidebar (Ctrl/Cmd+Shift+G), opening on the repository of the current session and keeping its own view, filters, splitters, and draft per repository.
- **Repositories**: the **+** menu clones a remote or selects a local repository; the repository dropdown supports name search.
