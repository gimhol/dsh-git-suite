# 使用与功能

[English](USAGE.md) | 中文

`dsh-git-suite` 为 DSH Web 增加 Git 面板：提交历史、分支、差异、提交、PR 以及常用的远端操作。

## 使用

- **在哪里打开**：左侧栏的 **Git** 入口、右侧面板开始页的 **Git** 卡片，或在任意位置按 **Ctrl/Cmd+Shift+G**（可在 DSH 的键盘快捷键设置里改）。两处是同一个面板。
- **选仓库**：用项目下拉（可输入过滤）或旁边的 **+** 菜单**克隆远端**/**选择本地**仓库；右侧面板默认打开当前会话所在仓库。
- **三个视图**：第二行的 **历史 / 提交 / PR** 切换。历史显示提交路线图与详情，提交显示工作区；当远端是 GitHub、Gitee 或 GitLab 时出现 PR，列出该平台的拉取/合并请求。
- **提交**：整文件用行尾按钮暂存、单个块用 **暂存此块**、拖动选中行后在右键菜单里暂存；写提交信息（↑ 可回溯本仓库历史信息）后点 **提交**。可选 **修改最后一次提交** 与 **提交后推送**。
- **差异**：每个差异都能在统一视图与分栏视图之间切换，并按文件语言做语法高亮（支持常见 50+ 种语言，未知类型保持纯文本）；Markdown 的 fenced code 也按语言高亮。`.m` 当前按 Objective-C 处理，MATLAB 代码块请使用 `matlab` 标注。
- **其它操作**：右键分支、标签、贮藏、远端、提交、文件都有对应菜单（检出、合并、变基、拣选、重置、贮藏、打标签……）；提交的「合并到当前分支…」弹窗支持 Git 的合并参数（`--no-ff`、`--ff-only`、`--squash`、`--no-commit`、`--allow-unrelated-histories`）和自定义合并信息。右上角按钮可在命令行、文件管理器中打开仓库，或用检测到的编辑器打开（VS Code、Insiders、Cursor、Windsurf、VSCodium、Zed、Sublime Text、TextMate、JetBrains 系列 IDE、Visual Studio 或 Android Studio）。
- **提示**：推送/拉取/获取、提交、分支/标签操作的结果与错误显示在顶部，每条都带关闭按钮；成功类提示约 6 秒后自动消失。

## 功能

- **提交历史**：分页加载、提交路线图、提交详情与逐文件差异（统一视图或左右分栏）；表头与列宽可调，虚拟滚动。
- **引用树**：分支、标签、远端、贮藏、子模块，支持搜索；双击本地分支切换工作区；子模块可打开并返回父仓库。
- **提交与文件状态**：整文件、单个 hunk 或拖动选中行的暂存/取消暂存，查看差异，提交或修改最后一次提交，提交后推送，以及 AI 生成提交信息。
- **Git LFS**：LFS 跟踪的图片/音频经 smudge 过滤器读取真实内容（本地缺少对象时提示未下载，而不是显示破图）；提交详情和工作区差异把 LFS 文件显示为指针的「对象 id + 大小」变化，而不是 `version`/`oid`/`size` 三行文本；文件列表用 **LFS** 标记代替指针行数；这类文件只能整文件暂存，按块/按行暂存会被拒绝，以免把指针改坏；AI 生成提交信息、暂存评审和 PR 草稿在发给模型前会把指针段换成对象说明；LFS 出错（缺少 git-lfs、对象未下载、远端拒绝 LFS 上传）会返回明确的 `lfs-failed` 提示而不是原始过滤器输出。
- **远端操作**：历史/提交切换，拉取/推送/获取（可选远端、分支、prune、标签、强制推送），合并/变基、变基到任意提交，提交右键标签/分支/检出/合并/拣选/反向提交/重置。提交合并弹窗支持 `--no-ff`、`--ff-only`、`--squash`、`--no-commit`、`--allow-unrelated-histories` 与自定义合并信息；合并因冲突停下时由冲突提示条继续或中止。
- **PR**：浏览 GitHub、Gitee、GitLab 远端上开放中、已关闭或全部的 PR/MR（搜索过滤已加载条目，滚到底自动加载更多），查看描述与讨论（均支持 Markdown 渲染）、评审与 CI 状态、提交、改动文件（逐个文件的语法高亮差异）；描述/AI 审查/文件/提交/讨论都可以单独收起，讨论固定在详情最下方，在浏览器中打开、检出为本地 `pr/<编号>` 分支（检出前会检查 `git status`，有未提交内容会直接拒绝并提示）、合并（按平台支持 merge/squash/rebase，可删源分支）、关闭，已关闭的 PR 可重新打开；也可以从当前分支创建新 PR（标题、描述、目标分支、草稿）。详情里的「AI 审查」点击后会先弹窗选择审查方式：临时检出（读取完整文件后删除 worktree）、完整文件（平台 API）、仅 Diff；上次选择会记住。AI 审查结果按 Markdown 渲染（标题/列表/代码块/表格/链接）。审查过程中会实时显示思考过程、输出预览、尝试次数和字符进度，可随时停止；diff 与完整文件预算会按模型上下文窗口自动调整。结果只留在页面、不会发到平台。Gitee 的合并弹窗会显示「审查通过」「测试通过」按钮，调用对应 API 标记状态；详情和弹窗同时显示审查/测试状态（未指派/待通过/部分通过/已通过）。它们只标记状态，不执行测试。GitLab MR 额外提供「删除 PR」，需要勾选危险确认，永久删除且不删除源分支；GitHub/Gitee 没有删除 PR 的 API，只能关闭。列表和详情在视图打开时每分钟静默刷新。私有仓库使用 `GITHUB_TOKEN`/`GITEE_TOKEN`/`GITLAB_TOKEN`、`gh` 或凭据助手中的令牌；令牌只经凭据助手保存，不进入页面。
- **跨仓库 PR**：把上游仓库添加为远端（如 `git remote add upstream …`），在 PR 工具栏选中它；工具栏胶囊会显示当前仓库，详情会显示 `head → base` 仓库归属。当前分支需跟踪自己的 fork 远端（如 `origin/feature`），创建表单就会开一个 fork → 上游的 PR。两个远端必须在同一平台和主机。查看、检出、关闭、合并上游已有的 PR 也只需选中上游远端。
- **凭据**：推送/拉取因认证失败时会弹出用户名/令牌对话框，凭据通过仓库的 git 凭据助手写入系统凭据管理器，并自动重试一次（SSH 远端则提示用 ssh-add）。
- **右侧面板**：同一面板可在 DSH 右侧面板打开（Ctrl/Cmd+Shift+G），默认打开当前会话所在仓库，并按仓库分别记住视图、筛选、分栏尺寸与草稿。
- **仓库**：**+** 菜单克隆远端或选择本地仓库；仓库下拉支持按名字搜索。

实现与构建管线见 [STRUCTURE.zh.md](STRUCTURE.zh.md)。
